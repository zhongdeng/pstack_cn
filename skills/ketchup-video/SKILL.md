# Ketchup 视频

遵循 [`/ketchup`](../ketchup/SKILL.md)，但用一段短的带字幕视频来展示发生了什么，而不是它的总结和图示。它的窗口从用户在 `/ketchup-video` 之前所写的上一条消息开始，而不是从任何更早的 `/ketchup` 之前开始。在仓库之外编写并渲染这段视频，是它只读规则的唯一例外。回复是 ketchup 的开场句、嵌入的视频、一行点明你自己还能做的剩余工作，以及待办项。当视频展示了某个决定的选项时，每个选项都用视频给它的名字来称呼。如果渲染失败，用一行说明，并且只给出这些决定。

## 幻灯片

使用工作产出的截图、录屏、diff 和数据，而不是对话里关于它们的散文。在你画之前，写下用户离开时应该带走的那一句话，以及每张幻灯片一行。丢掉每一张不改变用户所知的幻灯片。最多用 10 张，更少更好。这两份笔记都不放进回复。

每张幻灯片只讲一个点。把幻灯片建立在一张图上，并一张一张地改它，而不是切到一张无关的图。一种颜色或形状在每张幻灯片上意思相同。用图来展示工作，例如一个系统如何工作、一个标出每个 PR 状态的 PR 栈、一次修复的前后对比，或并排的选项。用箭头、高亮和运动指向变了的地方。幻灯片绝不是要点列表、状态列表、表格，或彼此没有连接的方框。

文字保持到最少。把每个标签放在它所命名的东西上，用一个人会说的白话，而不是「Tests: pass」这样的标签。绝不要为图片所展示的内容加说明文字，也绝不要把一个事实说两遍，无论是跨幻灯片，还是在它们下面的文字里。

展示用户要求的每一件事有了什么结果，以及它是完成了、仍在运行、失败了，还是没有检查。绝不要把仍在等用户的东西展示成完成。展示沿途发现并修好的任何缺陷。如果一个看得见的变化没有截图，就在它的幻灯片上这么说，并点名屏幕上变了什么。只根据你拥有的事实来画。绝不要编造数字，也绝不要画你没有截到的屏幕。

## 字幕

给每张幻灯片一行短字幕，大约十个词，用你会对用户说的方式说出它的要点，并且只根据那张幻灯片所显示的内容。说这张图意味着什么，而不是把上面的标签读出来。把字幕放在幻灯片下方的一条带子里，每张幻灯片上高度相同，除了字幕什么都没有，这样它绝不会盖住幻灯片。把它设得小，但在视频以聊天尺寸播放时仍然可读。

## 渲染

渲染一段静音的横向视频，例如 mp4，幻灯片之间有运动。每一帧就是幻灯片本身，边到边，位于它的字幕带之上。帧由幻灯片制作，绝不要靠录制屏幕，并把每条字幕烧进它那张幻灯片的帧里，这样它在这张幻灯片的整段停留期间都留在屏幕上。停留是一张幻灯片完全在屏幕上的时间，不算进入或离开它的运动。每张幻灯片停留足够长的时间，好读完它增加的词，每三个词至少一秒。一张幻灯片增加的是它的字幕，以及上一张幻灯片上没有的每一个词，包括它改掉的一个标签。第一张幻灯片增加它的全部词。截图内部的文字不计。

在嵌入视频之前，检查渲染出的文件。以聊天尺寸看每张幻灯片的一帧，并检查它的字幕可读、而且没有盖住任何东西。通过把文件的帧对上这张幻灯片来测量每一段停留，不要用静止帧检测器，它会把淡出末端的淡影也算成静止。把每张幻灯片增加的词数对照它测得的停留。任何你在那段时间里读不完的幻灯片都要修，重新渲染，再检查一次。
