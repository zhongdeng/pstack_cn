# Ketchup 视频

遵循 [`/ketchup`](../ketchup/SKILL.md)，但用一段带字幕的短视频展示发生了什么，代替它的总结和图示。它的时间窗口从用户写下 `/ketchup-video` 之前的那条消息开始，而不是更早的某次 `/ketchup` 之前。在仓库之外编写和渲染视频，是它只读规则唯一的例外。回复内容是 ketchup 的开场句、嵌入的视频、一行说明还有哪些你能自己做的遗留工作，以及行动项。当视频展示某个调用的选项时，用视频里给每个选项起的名字来称呼它。如果渲染失败，用一行说明，然后只给出这些调用。

## 幻灯片

用工作产出的截图、录屏、diff 和数据，而不是聊天里关于它们的文字。动手画之前，先写下用户应该带走的那一句话，以及每张幻灯片一行说明。凡是不会改变用户认知的幻灯片，删掉。最多 10 张，越少越好。这两份笔记都不放进回复。

每张幻灯片只讲一个点。所有幻灯片都基于同一张画面来构建，逐张改动它，而不是切到一张不相关的画面。同一种颜色或形状在每张幻灯片上含义相同。用画面展示工作，比如一个系统怎么运转、一个 PR 栈里每个 PR 的状态、一次修复的前后对比，或者并排展示几个选项。用箭头、高亮和动效指向变化之处。幻灯片绝不能是项目符号列表、状态列表、表格，或者彼此毫无关联的方框。

文字保持最少。每个标签放在它所命名的事物上，用普通人会说的平实词语，而不是 "Tests: pass" 这类标签。绝不给画面配说明文字，也绝不在幻灯片之间或下方文字里把同一个事实说两遍。

展示用户提出的每件事的结果，以及它是已完成、仍在运行、失败，还是未检查。绝不要把仍在等用户处理的事展示成已完成。展示过程中发现并修复的任何 bug。如果某个可见的改动没有截图，就在它的幻灯片上说明，并写出屏幕上改了什么。只依据你掌握的事实来画。绝不编造数字，绝不画你没有截取过的画面。

## 字幕

给每张幻灯片配一行简短字幕，大约十个词，用你对用户讲述的方式说出它的要点，只依据这张幻灯片展示的内容。说出画面的含义，而不是念出它的标签。把字幕放在幻灯片下方的一条字幕带里，每张幻灯片上高度相同，除字幕外留空，这样它永远不会遮住幻灯片。字号要小，但在聊天窗口尺寸下播放视频时仍要清晰可读。

## 渲染

渲染一个无声的横屏视频，比如 mp4，幻灯片之间有动效。每一帧都是幻灯片本身，铺满边缘，位于字幕带上方。帧由幻灯片生成，绝不通过录屏得到，并把每条字幕烧进它所属幻灯片的帧里，让它在整段停留期间一直显示。停留时间指幻灯片完整显示在屏幕上的时间，不含进入或离开的动效。每张幻灯片的停留时间要足够读完它新增的文字，每三个词至少一秒。一张幻灯片新增的内容包括它的字幕，以及此前不在幻灯片上的每一个词，包括它改动过的标签。第一张幻灯片新增它的全部文字。截图里的文字不计入。

嵌入视频之前，检查渲染出的文件。在聊天窗口尺寸下查看每张幻灯片的一帧，确认字幕清晰可读且没有遮挡任何内容。通过把文件的帧与幻灯片对应来测量每段停留时间，不要用静帧检测器，它会把淡入淡出的微弱尾段也算作静止。把每张幻灯片新增的词数与其测得的停留时间对照。凡是那段时间内读不完的幻灯片，修好，重新渲染，再检查一遍。
