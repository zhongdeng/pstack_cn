# 体验优先

当实现方便与用户愉悦冲突时，选择愉悦。

- 每个功能、控件和选项都必须有理由
- 少交付，交付得更好（三个功能的打磨体验，胜过十个功能的粗糙体验）
- 承诺之前先做原型（设计决策在可丢弃的 HTML 里比在生产代码里便宜）
- 把细节做对（过渡、对齐、间距、反馈、错误状态）
- 收紧核心循环（每个功能都应服务于中心工作流，否则就让开）

用户是消费这份工作的人。对 UI 来说是最终用户。对库或内部 API 来说是导入它的同事。接下来维护这段代码的工程师也是用户。用同样的方式权衡他们的体验，并从他们的视角解释影响。

基础应当为体验服务。基础性思考管的是工作的*顺序*。这条原则管的是*目标*。
