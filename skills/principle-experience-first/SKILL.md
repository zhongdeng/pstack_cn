# 体验优先

当实现上的方便和用户的愉悦冲突时，选愉悦。

- 每个功能、控件和选项都必须有存在的理由
- 少发，发好（三个功能打磨到位，胜过十个功能粗糙上线）
- 先做原型再定稿（设计决策在一次性 HTML 里改比在生产代码里改便宜得多）
- 把细节做对（过渡、对齐、间距、反馈、错误状态）
- 收紧核心循环（每个功能要么服务于主流程，要么让路）

用户就是消费这份工作成果的人。对 UI 来说，是终端用户。对库或内部 API 来说，是 import 它的同事。接下来维护这段代码的工程师也是用户。同样权衡他们的体验，并从他们的角度解释影响。

基础应该服务于体验。基础性思考管的是工作的*顺序*。这条原则管的是*目标*。
