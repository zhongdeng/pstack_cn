# 测行为，不测实现

测试是对代码为其用户做了什么的一个主张：调用方、终端用户，或另一个服务。行为就是这些用户通过他们使用的接口能观察到的东西。包括返回值、错误、他们能读回的状态，以及对外部系统的影响，比如发出一个请求、写入一行、发出一条消息。实现是他们观察不到的东西：私有辅助函数、内部调用顺序、中间数据，以及哪个内部协作者干了活。

用两个假想的改动来检验每个测试：

- **弄坏行为。** 让代码返回错误的值、跳过某个效果，或把效果做两次。如果测试仍然通过，它什么也没证明。常见原因是断言比契约更松、期望值由被测代码自己算出来、复述一个常量或提示词字符串却从不运行读它的代码，以及断言测试自己造出来的数据。
- **改内部实现。** 保持所有可观察结果不变，重构底下的代码。如果测试现在失败了，它就是钉在实现上。每次重构都要重写，却仍然抓不到 bug。

保留能抓住第一个改动、又能扛过第二个改动的测试。其余的改写或删掉。要写出两者都做到的测试，用具体的输入通过用户的接口驱动代码。期望值从需求推导，不从跑一遍代码推导。断言契约承诺的东西，不多不少。

决定的是契约，不是断言的形状。当承诺是"空购物车永不扣款"时，断言支付客户端没被调用就是行为。配上一个真的扣款的用例，让测试证明它看得见调用。被 mock 的外部服务收到的 payload 是行为，因为那个服务观察得到它。对内部辅助函数的调用是实现，因为没有用户看得见。没有记录匹配时，空列表就是精确的答案；测试只需要某个结果时，空列表就是空洞的检查。精确的错误消息钉住的是没有调用方会读的措辞。调用方据以分支的错误类型才是契约。

测试可以钉住一个不变量而不是一次调用，比如两张表里都必须存在的键，或编译期的类型检查。不变量就是行为。
