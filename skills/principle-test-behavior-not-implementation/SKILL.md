# 测试行为，而不是实现

测试是对代码使用者能通过接口观察到的东西的断言：返回值、错误、他们能读回来的状态，以及对外部系统的影响。私有辅助函数、内部调用顺序和中间数据是实现。

用两种假想的编辑来评判每个测试：

- **打破行为**（错误的值、被跳过或做了两次的效果）。测试仍然通过，它就什么也没证明。常见原因是断言太松、期望值由被测代码算出来，以及断言打在测试自己构造的数据上。
- **改内部实现**，每一个可观察结果都保持不变。测试失败了，它就是钉在实现上的。

留下能抓住第一种、又能熬过第二种的测试。其余的改写或删除。用一个具体输入，从公开接口驱动代码，期望值从需求推导，不要从跑一遍代码推导。外部服务收到的内容是行为。对内部辅助函数的一次调用不是。把「这件事从不发生」配上一个它确实发生的用例。断言调用方用来分支的错误类型，不要断言消息文本。
