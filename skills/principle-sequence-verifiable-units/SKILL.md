# 把工作排成可验证的单元

把工作排成小单元，每个单元结束在一个你能检查的状态，当前这个还没绿，就不要往下走。

扫荡、迁移或一连串相似编辑里，每个单元是一截：已知良好的状态，一次改动，跑检查，再继续。即使有工具在做编辑，每个单元的检查也要跑。

按能证明工作的顺序交付：先是失败的测试，然后是修复。先减，再重塑。先采基线，再做处理。每一次提交都能单独落地。
