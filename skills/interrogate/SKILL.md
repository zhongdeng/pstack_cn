# Interrogate

对抗方尝试打破一个改动或一个设计。只有被一次运行证明的发现才能留下。报告这些发现。不要应用修复。

## 框定

范围就是用户指定的东西。否则就是从与基础分支的合并基点开始、穿过工作区的分支 diff。用 **in-your-own-words** 技能，从用户的消息、提交和 PR 描述里说出意图。意图不清楚时问用户。

## 铺开

运行 **arena** 技能的 Phase A 第 3、4 步和 Phase B，用四个改动。读 `interrogate reviewers` 那一行，用来代替 `arena runners`。把范围里未提交的改动复制到每个 worktree。把每个对抗方作为 `generalPurpose` 启动。用范围、意图和下面这段简报，代替 arena 的任务和理由：

> 打破这个改动。每个发现都要用一次针对真实代码的运行来证明，比如一个失败的测试、一个复现脚本，或者能显示错误行为的命令输出。对于设计或计划，跑一个原型，或者探测当前代码树。复现留在你自己的 worktree 里。报告每个发现时给出标题、确切的命令、它打印的输出，以及意图所要求的输出。没跑过的东西不要写。这包括风格、命名、结构，以及需要未来改动才有意义的风险。没有发现也是有效结果。

## 验证

按 arena Phase F 验证每个发现，重跑它的命令。当输出显示出失败，并且这个失败破坏了意图时，保留该发现。其余的丢掉。合并根因相同的发现。

跳过 arena 的 Phase C、D 和 E。对抗方找到的失败各不相同，所以结论保留每一个已验证的发现，而不是某一个对抗方的清单。

## 输出

- **Intent**：意图的复述。
- **Findings**：对每个已验证的发现，给出命令、它的输出、它如何破坏意图，以及哪些对抗方发现了它。没有发现留下时说 "no verified findings"。
- **Dropped**：对每个对抗方，给出被丢掉的发现数量和原因。
