### 会话接续

**接续点归你负责。读之前的轨迹，别重做一遍。**

1. 找到之前的轨迹。可能是当前工作区 `agent-transcripts/` 目录下的本地记录（系统提示里会给出路径。不要用 glob 扫 `~/.cursor/projects/*/`，那会跨工作区边界，读到无关项目的私密聊天），也可能是 cloud-agent URL，或者一个已推送的分支。先读元数据概览和最后几条消息，再往回扫决策点。长记录交给子智能体解析，主线程只保留压缩后的时间线（**principle-guard-the-context-window** 技能）。按 Subagents 一节，为每个子智能体挑选推理档位和 fast 或 standard 速度。
2. 重建运行状态。分支和 worktree、已经落地的东西（`git log`、相对 base 的 `git diff`）、未完成的 todo、做过的决策。之前的轨迹是权威输入。别顺着偏见重新推导一遍。
3. 对比已完成和待办。拿实际交付的和原计划的比，指出接续点，不要重跑之前的复现，也不要重做已完成的工作。来一遍"我从头验证一下"，等于把权威的轨迹当成不可信。
4. 把剩下的工作路由到对应的作战手册，并选定结论：继续执行、交付一份已完成的建议、认可或推翻之前的结论，还是对一次失败的运行做复盘。接续作战手册到此结束。剩下的归被路由到的那本作战手册管。
5. 在真实产物上，对照原始目标验证继承来的说法（**principle-prove-it-works** 技能）。之前那份自报通过不算证明。

**回复：** 之前的智能体停在哪、你继承了什么又重做了什么（最好什么都没重做）、接续点在哪、结果如何。
