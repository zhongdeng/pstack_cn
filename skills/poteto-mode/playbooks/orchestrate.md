### Orchestrate

**项目由你负责，代码从不由你负责。撰写简报、排空队列、保持前沿绿色、做决定。** 用于把整个项目交给一个常设的协调者对话：多日、许多堆叠的 PR、几十到几百个子代理，人一天来看两次，而不是每五分钟一次。把一个任务开到一个谓词是自主运行。一次需要定制工作流的雄心勃勃的运行是 figure-it-out。当工作比任何一个单独的代理都活得更久时，路由到这里。一个代理在本次会话预算内就能做完的工作不是项目，不论措辞听起来多么像一个项目。

仪式必须随项目伸缩。对廉价且几乎相同的单元，按每一节的指示把仪式收掉。

三条规则带着其余的一切。

- 完成是队列事件，不是中断。
- 每一次派生和每一次恢复都逐字带上长期指令。
- 简报就是产品。含糊的简报会安静地失败，因为工作者不能向你提问。

#### 角色与安置

- **协调者（本对话）。** 本地。框定、撰写简报、排空收件箱、拥有给人的报告、做出判断。它从不编写或编辑代码。有冲突的合并、链式变基和代码改动永远是任务。把一个已验证单元机械地合入（对工作者的提交做快进，或做一次干净的拣选，然后推送）是簿记，在本地 git 便宜的仓库上，协调者可以自己做。把做完的工作排在一个闲着的堆叠者后面，截止日期就会颗粒无收。这个循环端到端都是代理式的。代理只通过 Task 工具被派生、恢复和排空。按子代理一节，为每个子代理选择这项工作所需的推理档位，以及 fast 或 standard 速度。状态的读和写在排空点经过 `scripts/orch/orch.ts`，一条命令进去，一行出来。CLI 从不派生、等待或唤醒任何东西。
- **子协调者。** 始终在本地、持久、每条轨道一个，并且只在项目超出一个协调者的排空所能处理时才设。一条协调者自己排得空的轨道不需要中间层。每一层嵌套都要重新付一遍完整的定向开场，而一个阻塞的子协调者会在父级闲着时把它的子级藏起来。拥有本轨道的单元和看板，撰写其工作者的简报，派生自己的工作者和验证者（嵌套到第 3 层仍然有效，并且一次嵌套派生拥有完整的 Task 模式，包括 `environment`）。在波次边界汇总合计。从不转发子级的原始报告。在途子级的上限是一次排空能处理的数量，大约十个，作为滚动窗口。绝不要做成阻塞批次，那会让每一批都付出最慢那个子级的代价。
- **工作者 / 验证者。** 始终 `environment: "cloud"`，除非任务需要这台机器：来自 `cursor-team-kit` 的 `control-ui` 或 `control-cli` 运行时验证。读取 `agent-transcripts/` 下的本地记录。模拟器和本地 IDE 状态。只存在于这里的认证。云代理读不到本地存储，所以它们的简报把需要的内容内联进去，或指向仓库路径。偏好更少、更宽的工作者。每个工作树或分支一个写入者（principle-separate-before-serializing-shared-state）。一个单元的验证者要用与其工作者不同的模型家族来跑。

深度停在协调者、轨道、工作者。按项目来撰写轨道分解（构建、合入和验证是常见的切法，不是规定的形状）。硬编码的 swarm 树试过，因太死板而搁置。

#### 存储布局

在当前代理的存储里创建 `orchestrate/<project-slug>/`（路径在系统提示里）。每个文件恰好一个写入者。所有者发布事实，读者在读取时汇总。簿记用 `bun scripts/orch/orch.ts`，下文写作 `orch`，同时它规范的纯 TSV 和 JSON 不用 CLI 也能读。

- `preferences.md` 是长期指令登记册：编号的行，每行一条约束（模型策略、栈的形状和数量、验证门槛、禁止的路径、升级策略）。把它逐字贴进每一次派生和每一次恢复。指令会在一次次恢复中衰减，每丢掉一条就耗费人的一个回合。当你发现自己在重述一条指令，先把这一行追加进去再行动（principle-encode-lessons-in-structure）。
- `overview.md` 是持久的 PR 和议题库。追加。绝不要按事件整篇重写。
- `units.tsv` 每个单元一行：id、track、state、branch、PR、head SHA、brief path。就地更新行。
- `frontier.json` 是计算出的合并前沿，见栈安全。
- `ledger.tsv` 是验证台账，见验证。
- `inbox/` 放完成指针。`gates.md` 停放人的门禁（问题、选项、没有回答时的默认）。
- `decisions.tsv` 是经 show-me-your-work 技能留下的痕迹。
- `status.md` 在每次排空时从 `units.tsv` 和 `ledger.tsv` 推导，绝不手工维护。从表格重新生成它，而不是把事件叙述写进去。

#### 简报

你给代理的提示是你唯一的产品，一份潦草的简报会在整棵树上复合成 AI 腔。每一次派生都带上它的全部。一个填不上的字段，就是一个你还没划定范围的单元。

```
GOAL         one sentence, the outcome, executable by a stranger with no chat access
SCOPE        paths this unit may write; paths it may not; its exclusive worktree or branch
CONTEXT      pointers to files and PRs; upstream reports pasted in full when this unit
             depends on them, because workers cannot see siblings
ACCEPTANCE   checkable criteria, one per line
VERIFY       exact commands or the control-skill path, plus known gotchas
TIMEBOX      rough cap on runtime; on expiry, return partial findings and stop rather than run on
FORBIDDEN    no PR retargets or merges, no rebase, no force-push, no fixes outside scope,
             plus unit-specific bans
REPORT       status, branch, head SHA, PRs, verdict, what you actually ran, deviations,
             suggested follow-ups
STANDING     <preferences.md pasted verbatim>
```


按单元来定简报的篇幅。一个一条命令的单元，把模板收成一段，这段仍然点名 goal、scope、验证命令和报告形状。围着两行编辑搭 4KB 的脚手架，写它和遵守它的代价都超过那次编辑。本地派生可以按存储路径引用长期指令文件。逐字粘贴用于云派生和每一次恢复。

子协调者的简报再加上它的轨道边界和单元列表、派生预算（含云默认值和本地例外清单）、排空协议，以及汇总格式（每个子级：name、status、PR、head SHA、verdict、一行，外加轨道状态和前沿增量）。

依赖是上下文的接力，不只是排序。未声明的上游上下文会让工作者去猜。缺字段就是拒绝派生的条件。每个子协调者每一波抽一份工作者简报来审计，与它所抽的那一波同时进行，绝不要做成挡在它前面的门禁。一份不合格的简报停掉那条轨道，并修正子协调者的指令，而不只是那个工作者，因为简报质量会在运行后期衰减。绝不要用恢复把简报串起来。用合并后的范围重新派生一个全新的。

#### 步骤

1. **框定。** 把完成谓词说成可数的东西（「全部 126 个单元已合并，每一个都在台账上验证为 `unit-test-verified` 或更好」）。量化范围：单元、大致工作量、预期的栈，以及挂钟时间预算。如果一个代理能在那个预算内做完，就停在这里，改跑自主运行。收掉仪式不得依赖另一份文档在场。它的意思是在本次会话里直接做这项工作，有帮助时用普通工作者，验证内联，边做边合入，并且不要下面的存储、登记册或试点机制。按预算安排合入。大约到预算的 70% 时，停止派生，把已验证的合入。按项目点名轨道。有争议的分解或一扇单向门，在试点之前走 arena 技能。框定只呈现一次。可逆的准备工作不等待就继续。
2. **安装运行时。** 运行 `orch init`。经 show-me-your-work 技能打开痕迹，在任何派生之前写下长期指令，并用 `orch frontier set --repo <repo-dir>` 从已有 PR 播种 `frontier.json`，当托管平台是 Origin 时加上 `--forge origin`。
3. **试点。** 把一个单元推过整条路径：简报、工作者、验证、入栈、台账行、合并。试点的存在是为了证伪简报模板、验证配方和单元大小，此时代价是一个代理而不是五十个。在任何扇出之前，根据试点证据修正契约。按单元来缩放试点。在由几乎相同的廉价单元组成的项目上，第一个单元就是试点，作为普通单元来跑，验证命令内联，它一合入就开始扇出。专门的试点流水线（单独的验证者代理、审计门禁）用于昂贵或新颖的单元形状，不用于克隆单元，串行试点在那里没有什么可证伪的。
4. **扩展。** 派生一个不超过在途上限的工作者滚动窗口，子级完成就回填。阻塞批次会为每一批付出最慢子级的代价。只有超过角色一节里那个一次排空的阈值，才派生轨道子协调者。每次排空后重新计算就绪的工作。把上游报告接力进下游简报。同级通信只向上。抽查的简报审计与它所抽的波次并行，失败时停掉下一次回填，而不是当前这一次。
5. **排空。** 在每个排空点执行下面的队列纪律。
6. **合入。** 合入是连续的，绝不是一个收尾阶段。集成从第一个已验证单元开始，与剩余波次并行。在重仓库上，堆叠者从第一波起就是常设角色，单元一验证就集成。在本地 git 便宜的仓库上，协调者按角色一节自己合入已验证单元。做栈上方的工作之前保持前沿是绿的。栈安全说了算。只在合并或报告了新的 head SHA 时推进 `frontier.json`。
7. **结束。** 排空最后的收件箱，把每一个派生过的代理对到一个终态行（done、abandoned、zombie-reconciled），在真实产物上确认谓词，确认每一个已合入的 PR 对其当前 head SHA 都有裁决，按 show-me-your-work 审计痕迹，包括它的跨模型审查，把反复出现的修正编码进 `preferences.md` 或简报模板。存储原样留下。它就是复盘。

#### 队列与排空

- 收到完成通知时，运行 `orch inbox push <agent> <unit> <status> [--report PATH]`，然后回到你正在做的事。绝不要在线做深度审查。需要审查的完成变成一个验证者单元。绝不要在一次排空里面审查 diff。
- 在四个点分批排空：临界区结束、一次轨道汇总、前沿看守被唤醒（通过 loop 技能启用它，并以长心跳为后备），以及给人报告之前。每一批以 `orch inbox drain` 开始。排空期间到达的项等下一次。
- 你要先做完的临界区：撰写简报、一次栈操作、一个冲突决定、写一条门禁、更新台账或前沿。
- 每次排空给每个指针分类（landed、needs-verify、failed、zombie、noise），通过 `orch unit add`、`orch unit set` 和 `orch ledger record` 写下结果行，运行 `orch status`，然后在一条消息里派生下一波。
- 在轨道汇总时交代每一个派生过的子级：arrived、respawned，或它的范围被明确吸收。悄悄重做失踪子级的工作，既掩盖了浪费的开销，也掩盖了它的结果本来要补上的覆盖缺口。
- 排空回合以 `orch status` 的三行结束：对照各状态的计数、变了什么、开着的门禁。细节在 `status.md`。完整的回复契约适用于检查点和结束。

#### 栈安全

- 前沿是一个计算出来的对象，绝不是叙述。每次合并和栈变动之后重算 `frontier.json`：有序的 PR 列表、分支名、head SHA、一个世代号、最低的未合并 PR。这条命令顺着检出的当前分支走 PR 的基分支链，所以链的顺序和 PR 状态来自托管平台。它默认使用 `gh`。当项目把托管平台解析为 Origin 时，传 `--forge origin`。head SHA 来自本地分支引用，所以从堆叠者的克隆来解析。没有 PR 的分支报错，而不是去猜。
- 每个栈恰好一个堆叠者可以改拓扑（链式变基、强制推送、基分支改目标、合并），在其栈内串行。把持有者记在长期指令里。链式变基在云上跑。这个规模的本地变基会把笔记本拖垮。
- 工作者从不变基，也从不改 PR 目标或合并 PR。Babysit 执行者遵循 `playbooks/babysit.md`，每个栈一个，范围限定在一个不可变的前沿世代。它们把冲突报告给堆叠者，而不是自己变基。
- PR 的关闭和改目标只经过堆叠者。关闭一个基 PR 会让它上面的整条链变成孤儿。合并和栈手术是单元，和其他单元一样有简报。
- 一个回溯看守跟踪已合并的 PR，看回滚、合并后的 CI 损坏，以及孤儿后续。

#### 验证

按单元来缩放验证。当 VERIFY 是一条廉价命令时，工作者运行它并报告输出，协调者抽查回执。专门的验证者代理（模型家族与工作者不同）用于验证昂贵、依赖判断或爆炸半径大的单元。一个验证者代理如果全部产物只是重跑一条命令，那是仪式，不是验证。

用 `orch ledger record` 写台账行。用 `orch ledger check` 检查当前 PR 和 head SHA。`ledger.tsv` 每个裁决一行，键是 PR 号加上 head SHA：`live-ui-verified | unit-test-verified | type-check-only | verifier-blocked | verifier-failed`。CI 变绿是裁决的输入，不是裁决。行为方面的工作需要好于 `type-check-only`。`verifier-blocked` 不算通过。环境恢复后再派生。`verifier-failed` 得到一个修复单元，而不是重新验证。工作者可以自报。验证者在同一个键上覆盖它。新的 head SHA 使该行失效，所以重新堆叠后要重新验证。台账回答的是「这验证过了吗」，不是记忆，也不是记录稿。

一个单元在合入的那一刻把输出外化之前不算完成，绝不要攒到运行结束。工作者推送自己的分支，验证者写下台账行，回执落进存储。只存在于一台虚拟机上的工作，在那台虚拟机死去时，等于从来没做过。

#### 存活与失败

- 绝不要为了查看一个代理而恢复它。恢复会重新启动一个闲置的代理。只读探查：台账、`units.tsv`、`gh`、已推送的分支、Cursor 仪表板上云代理的状态。记录稿的 mtime 不是存活。
- 无声死亡在收件箱里得到一行合成的复盘（单元、失败模式、最后的证据、选项）。证据一到就重新计划。绝不要等完全静止。
- 按模式重试：cap-hit 或 oom，用更小的范围重新派生。Network-drop，原样重试。Tool-error，换一个模型重试。Unknown，重试一次。两次重试之后，放弃该单元并绕过它重新计划。
- 几个小时后才回来的僵尸，在接受任何东西之前，先对照当前前沿和台账对账。通过一个全新单元抢救独特发现，绝不要盲目合并。
- 当继续派生会在整棵树上产出垃圾时（上游输出是坏的、验收坏了、基础设施死了），在长期指令顶部写一行停止，让在途工作做完，修好原因，再清掉这行。
- 用约束子级的同样方式约束你自己的基础设施重试。连续几次工具中止之后，停止重试。把终态交接写进持久状态（做了什么、它在哪里、恢复的确切命令），并结束这次运行。
- Cursor 重启之后：本地代理是死的，云上的工作不是。重读长期指令和 `units.tsv`，重算前沿，按 PR 和分支而不是代理 id 重新接上云上的工作，每条轨道按它存着的简报加上当前状态重新派生一个子协调者，排空，继续。死掉的会话的存储锁会在下一次写入时自己清掉。`orch` 会替换持有者 pid 已经不在的锁。

#### 升级

要到人那里的，按批放进状态页，而不是逐条：不可逆动作（向共享分支强制推送、部署、删除、关闭别人的 PR）、实验无法裁定的真正产品或偏好决定、与观察到的现实矛盾的长期指令、重新计划之后仍然存在的项目级死胡同。询问之前先把每一条停放成 `gates.md` 的一条，并让工作绕开它。

绝不到人那里的：前沿的轻推、变基的机制、重试、CI 不稳定的分诊、审查线程的分诊、格式修复、简报已经禁止的范围（拒绝并继续），以及「should I keep going」。拿不准时，行动并记录。

运行中途的发现只修复挡住前沿的东西。其余的停进后续。在这种扇出下，一小点范围泄漏会乘成没人要求的 PR。

**回复：** 在检查点和结束时：谓词，以及从 `units.tsv` 和 `ledger.tsv` 得出的对照计数、各条轨道以及每一条合入了什么、前沿（PR 列表加上 SHA）、裁决摘要、放弃了什么以及为什么、等着人的门禁（仅有的请求）、存储路径和痕迹路径。数字来自表格，不是叙述。附上 PR 链接。
