### Autopilot-stack

**栈由你负责，合入从不由你负责。交给操作者一叠线性的、基分支串起来的 PR，供其审查并合入。** 除了已验证的工作如何离开，**Autopilot-full** 仍然成立。每次节拍都从主干重读两本手册，两者不一致时以这一本为准。

1. **跑 Autopilot-full 的负责人，去掉合入。** 负责人报告 STACK-READY，代替可合并。他们绝不把分支变基到另一条分支上，包括主干，也绝不改目标、合并、关闭 PR，或启用自动合并，因为链的拓扑归根所有，合入归操作者所有。当一项依赖另一项时，它的负责人从那一项的分支分出，不从主干分出。
2. **拓扑只给一个写入者。** 负责人只推送自己的分支，并报告每一个 tip 及其预定的父分支。只有你来变基或改一条链接的目标，因为一条链上有两个写入者会互相拆掉。按依赖顺序追加每一个干净的 PR，把它的基设成父分支的分支（`origin pr edit <pr> --base <parent-branch>` 或 `gh pr edit <pr> --base <parent-branch>`）。绝不要求 `gt`。负责人把你的推送当作它的新基和租约，冲突时解决它自己的那一片，供你推送。
3. **在根上吸收漂移。** 合入开始之前，对每一条链接应用 Autopilot-full 第 5 步的测试，并在它要求变基的地方自底向上变基整条链。然后逐条链接应用 patch-id 规则，因为一条链接的基就是它的父。
4. **交出这条链，然后把手拿开。** 每一条链接在它的 PR 里带着自己的裁决。合入一开始，除了 `playbooks/shipping.md` 所允许的合并后改目标，没有人再写这条链，因为第二个写入者会弄坏正在进行的合入。合入中途的问题经你交给操作者，任何修复都等操作者的放行。

**在两种自动驾驶之间选择。** PR 彼此独立且合入权已经授予时，用 Autopilot-full。操作者希望合入前先审查、工作有顺序或相互耦合，或合并权被扣下时，用 Autopilot-stack。

**回复：** 按 **ketchup** 技能把操作者补到最新，附上栈根和栈顶的链接、每一条链接一行裁决，以及任何停放或排除的项及其理由。
