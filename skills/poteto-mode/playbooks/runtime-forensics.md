### 运行时取证

**诊断由你负责。给活着的进程插桩，别对着源码空想。** 交付物是一份有据可查的诊断，不是修复。

1. 通过控制技能在对应的界面上抓取实时信号：进程空转就抓 CPU profile，内存泄漏就抓堆快照，视觉异常就抓 CDP trace。要拿到真实产物，不是猜测。
2. 把产物缩小到确凿证据：热路径上的那个函数、从泄漏对象到 GC root 的引用链、没有输入却仍在触发的循环。大产物交给子智能体解析（**guard-the-context-window** 原则技能），主线程只保留缩小后的结论。按 Subagents 一节，为每个子智能体挑选推理档位和 fast 或 standard 速度。
3. 先证明机制，再相信它。通过 CDP eval 在运行中的进程上注入插桩，或者不重新加载直接热修线上代码，用低成本的方式确认假设。
4. 把结论映射回源码：文件、符号、分配或调度的那一行。
5. 吞吐量检查点保持一行：`throughput checkpoint: n/a, read-only forensics`。

**回复：** 抓到的信号、缩小后的结论、你如何证明机制、源码位置、产物路径。除非被要求，否则不给修复。原因明确后，交回 Bug fix 或 Perf。
