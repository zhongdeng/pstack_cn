### 运行时取证

**诊断由你负责。给活着的进程装仪器，不要从源码空想。** 交付物是一份带引用的诊断，不是修复。

1. 经控制技能在对应的交互面上采集活信号：旋转进程用 CPU profile，泄漏用堆快照，视觉故障用 CDP 追踪。要真实产物，不要猜测。
2. 把产物收到确凿证据：热路径上的函数、从泄漏对象到 GC 根的保留链、没有输入也在触发的循环。在子代理里解析大产物（**guard-the-context-window** 原则技能），把收束后的发现留在主线程。按子代理一节，为每个子代理选择这项工作所需的推理档位，以及 fast 或 standard 速度。
3. 相信机制之前先证明它。通过 CDP eval 向正在运行的进程注入仪器，或不重新加载就热修补活代码，廉价地确认假设。
4. 把发现映回源码：文件、符号、分配或调度的那一行。
5. 吞吐检查点保持一行：`throughput checkpoint: n/a, read-only forensics`。

**回复：** 采集到的信号、收束后的发现、你如何证明机制、源码位置、产物路径。除非被要求，否则不给修复。原因清楚之后，交回缺陷修复或性能问题。
