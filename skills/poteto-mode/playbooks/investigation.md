### 调查

**答案由你负责。计划、路由、写下来。**

调查请求是只读的。它们产出一份带引用的解释或一条建议，不产出代码改动。

1. 经 **how** 技能路由。动机类问题还要经 **why** 技能路由。
2. 吞吐检查点保持一行：`throughput checkpoint: n/a, read-only investigation`。
3. 产出 `how` 形状的输出（Overview / Key Concepts / How It Works / Where Things Live / Gotchas），如果请求是在备选方案之间做决定，则产出一条带取舍表的建议。
4. 对回复应用 **unslop** 技能。

没有 PR，没有 Babysit，也没有 `architect`，除非这次调查发生在一次代码改动之前。如果是那样，交还给用户，并重新路由到缺陷修复或功能。

**回复：** 调查输出。对「are we sure?」这类回答，附上你真实的判断和理由。如果前提是错的，就推回去（见自治）。
