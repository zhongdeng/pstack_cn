### 重构

**契约由你负责。结构变。行为不变。** 与功能不同，功能增加行为。与缺陷修复不同，缺陷修复纠正行为。

如果清理暴露出一个缺失的功能或一个真缺陷，把它拆出去，先对照钉住的契约交付结构改动。允许重新设计，但要把它点名，并路由到功能。大的或横切的结构工作属于 **figure-it-out** 技能。这一本是聚焦到中等的改动。

1. 先钉住行为契约。对受影响的子系统运行 **how** 技能来了解契约，然后写一个特征测试、快照或等价装置，在任何结构移动之前抓住当前行为。如果这块没有覆盖，在碰结构之前先写好钉子。类型检查和 lint 不是钉子。
2. 按 **principle-model-the-domain** 点名代码缺的那种结构。形状已经清楚而且局部时，乏味的代码留着。重塑必须删掉分支或非法状态，而不是增加间接。
3. 点名目标形状。说明如果今天来建，模块布局、类型和调用图应该是什么样（**principle-foundational-thinking**、**principle-redesign-from-first-principles**）。如果目标跨过函数边界，在移动之前运行 **architect** 技能，对形状做并行的设计探索。
4. 先减后加。在引入新形状之前，删掉死代码，压掉只有一个调用方的包装，丢掉冗余的校验器，并移除孤儿引用（**principle-subtract-before-you-add**）。达到目标形状的最小改动才交付（**principle-laziness-protocol**）。一次「也许有用」的投机清理要回退。
5. 以小的、保持行为的步骤来移动，每一步都让钉子保持绿色。对 API 重塑，在同一波里迁移每一个调用方并删除旧 API（**principle-migrate-callers-then-delete-legacy-apis**）。不要兼容垫片，不要新旧并行的路径。对照实际文件抽查每一次重命名。重命名会悄悄漏掉字符串、散文和反向引用里的用法。把机械编辑委托给一个子代理，使用你配置的 refactoring 模型（默认 `grok-4.7-xhigh-fast`），并给一个具体范围（文件路径、被移动的名字、要守住的行为）。按子代理一节，为每个子代理选择这项工作所需的推理档位，以及 fast 或 standard 速度。
6. 在真实产物上证明行为没有变，不是「它能编译」（**principle-prove-it-works**）。对较大的重塑，跑一次等价检查：一个对比新旧输出的脚本、一段对着新代码重放的已记录基线，或经相关控制技能在对应交互面上的一次冒烟运行。
7. 确认这次改动值得保留。成功的度量是读者负担降低了（**principle-minimize-reader-load**）。如果 diff 没有在某处降低读者负担，就回退它。
8. 变基成小而有序的提交。一次减法提交，然后是重塑，然后是任何后续清理。用 **sequence-verifiable-units** 原则技能来塑造它们，让每一个保持行为的切片在下一个之前保持绿色。运行 **打开 PR**。

**回复：** 变了的结构、你拿它去对照的那颗钉子、等价证明、读者负担的变化、交付了什么、回退了什么。没有新行为。
