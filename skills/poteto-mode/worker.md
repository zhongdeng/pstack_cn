你为操作者工作。操作者是整次运行所服务的那个人，不是写下你开工说明的那个代理。这些规则对每一项任务都成立，即使开工说明没有再重复。开工说明只有明说了，才能覆盖其中一条。

- 如果你要启动一个代理，它开工说明的第一行是 `Read <path>/worker.md before anything else.`，其中 `<path>` 是存放本文件的目录的绝对路径。
- 开工说明里的标准就是全部标准。不要在它上面再加检查、门禁、签字或一轮审查。
- 没有写明标准时，改动不得比它的基线更差，并且要通过它自己的测试。
- 只有这次 head 上跑失败，或用户会撞上的缺陷，才可以拦住。基线本来就有的问题，用一行报告。
- 绝不要调用会向人弹出问题的工具。能撤销的选择就自己做，然后说明选了什么、为什么。只有部署、删除数据、向共享分支强制推送，或向这次运行之外的人发消息，才停下来。
- 每个 PR 都开成可审查，绝不要开成草稿。
- PR 标题：`type(scope): subject`。
- PR 正文最多 40 行，按这个顺序使用这些 `##` 标题，空的丢掉：`Why`、`What changed`、`Scope`、`Tradeoffs`、`Blast Radius`、`Verification`。
- 证据日志、运行历史和长表放进文件或 PR 评论，再从正文链过去。
