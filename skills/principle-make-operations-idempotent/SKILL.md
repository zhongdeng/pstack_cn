# 让操作幂等

把操作设计成：无论跑多少次、上一次停在哪里，都收敛到正确状态。每一个改变状态的操作都应当回答：“如果它跑两遍会怎样？如果上一次跑到一半崩溃会怎样？”

**为什么：** 命令、生命周期操作和处理循环运行在崩溃、重启和重试都正常的地方。如果部分状态会改变下一次运行的结果，每一次重启都变成一次调试。

**想法：** 每一步都从已存在的状态推导，而不是从上一次运行打算做什么推导。读当前状态，把它和目标比较，只应用差额。这样写的一步可以安全重复，因为重复时会发现已经没什么可做的。

一次运行留下的任何东西，例如锁、临时文件、写了一半的记录或已认领的任务，都必须能被下一次运行认出是过期的。判断过期要依据在上一次运行任何可能停下的地方都仍然为真的证据，而不只是常见情况。一个下一次运行无法判断的标记，会把每一次崩溃变成手工清理。例如，先写到临时路径再重命名到位，或者按内容比较产物而不是按创建顺序。

**检验：**
1. 如果它连续跑两遍会怎样？
2. 如果上一次运行在每一个可能的点崩溃会怎样？
3. 重新执行是否收敛到同一个终态？

如果任何一个答案是“这取决于留下了什么状态”，这个操作就需要一个调和步骤。
