# 让操作幂等

设计操作时，要让它们无论运行多少次、上一次运行停在哪里，都能收敛到正确的状态。每个会改变状态的操作都应该回答："如果这个操作跑两次会怎样？如果上一次运行中途崩溃了会怎样？"

**为什么：** 命令、生命周期操作和处理循环运行的环境里，崩溃、重启和重试都是常态。如果残留的部分状态会改变下一次运行的结果，那么每次重启都会变成一场调试。

**思路：** 让每一步都从当前存在的状态推导出来，而不是从上一次运行打算做什么推导出来。读取当前状态，和目标对比，只应用差异部分。这样写出来的步骤可以安全地重复执行，因为重复执行时已经找不到需要做的事。

一次运行留下的任何东西，比如锁、临时文件、写了一半的记录，或者被认领的任务，都必须能被下一次运行识别为过期。判断是否过期，要依据那些无论上一次运行停在哪里都成立的证据，而不只是常见情况。如果下一次运行无法判断某个标记是否过期，那么每次崩溃都会变成手动清理。例如，先写入临时路径再重命名到目标位置，或者按内容而不是按创建顺序比较产物。

**检验：**
1. 如果这个操作连续跑两次会怎样？
2. 如果上一次运行在每一个可能的点都崩溃过会怎样？
3. 重新执行会收敛到同一个最终状态吗？

如果任何一个答案是"取决于留下了什么状态"，那么这个操作就需要一个对账步骤。
