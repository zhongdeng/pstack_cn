# 解释这个数字

- **问“为什么不是两倍？”** 指出约束这个结果的资源或代码路径，例如一个核、一把锁、磁盘、网络，或负载发生器本身。从一次运行期间的 profile 或系统计数器得到它，再映射到源码。读代码猜出来的不是限制因素。如果你说不出这个数字为什么没有好一倍，你就不知道自己测到了什么。
- **列出这个数字还可能在测什么，并用证据逐一排除。** 常见嫌疑是错误、被跳过或被缓存的工作、从未运行的代码、一侧没有调优（留在默认设置）、噪声，以及一块小到端到端无关紧要的部分。
- **把证据和数字放在一起。** 把运行次数、散布，以及限制因素写进笔记或一份链接的产物。

对于性能数字，用 [benchmark-checklist](../benchmark-checklist/SKILL.md) 技能跑完整流程。对于 eval 结果，对试验问同样的问题：每次运行是否都做了任务，差距是否在各次试验和各个模型上成立，以及这个场景是否重要。

如果一个数字背后的证据没有运行次数、没有散布、没有点名的限制因素，或者省下的时间大于被改动的那一块原本花费的时间，你就跳过了这条原则。

它不同于 [证明它能工作](../principle-prove-it-works/SKILL.md)。后者检查的是输出是真的。
