# 设计红旗

综合之前筛过每一份候选。红旗是要修订或否决这个形态的理由。

## 浅模块

浅模块暴露很大的接口，却藏住很少的复杂度。判断深度，要看公开表面后面藏着的能力和策略，相对于这个表面的大小。优先选有充实行为撑着的简单接口。

不要把深模块和深调用链搞混。深调用链把理解散到各层。深模块把能力集中到一个接口后面。

找这些迹象：

- 调用方要协调好几个方法，才能完成一次操作。
- 公开的选项暴露了内部阶段或实现上的选择。
- 学会了接口，并不能让调用方免于去学实现。

## 信息泄漏

信息泄漏让多个模块依赖同一个内部决策。一种表示、一条策略或一处协议细节出现在不止一个地方，于是改它就要协调着改。

把传输类型或线上类型公开再导出，就是泄漏。在接口后面把外部数据解析成领域类型。存储 schema、框架对象和协议细节保持私有。

## 时间分解

时间分解按执行顺序组织模块，而不是按它们拥有的知识。把加载、校验、变换、保存拆开的阶段，常常把同一种表示和它的不变量在好几道边界上重复一遍。

围绕领域知识和所有权来组织代码。运行时刻不同的方法，只要保护的是同一批决策，仍然可以属于同一个模块。

## 透传方法

透传方法把同样的参数转给另一个形态相同的方法。它加了一层，却没有藏住复杂度。

删掉它，或者把职责挪到能完成这个操作的模块。只有当转发边界增加了策略、适配或一个不同的抽象时，才保留它。

## 所有权分裂

不止一个模块写同一份状态，或者各自留着它的一份拷贝。改了其中一个写入者的 agent 看不到其他写入者，于是它们的规则就分叉了。

每一份状态给一个所有者。其他模块读它，或请所有者去改。

## 一件事有两种做法

设计支持用不止一种方式做同一件事。agent 抄它最先找到的那种，于是每种方式都继续获得调用方。

只留一种。把调用方从其他方式迁走，并在同一次改动里删掉它们。

## 可导入的内部实现

调用方可以导入模块的内部实现。agent 走能编译通过的最短路径，于是直接导入它们，它们就变成接口的一部分。

让模块外部够不着内部实现，这样从外部导入就会让构建失败。

## 手工同步的清单

两个或更多地方列出同样的条目，加一条就意味着改每一份清单。只看到一份清单的 agent 只会更新那一份。

只留一份清单，其他的从它推导。如果某份清单推导不出来，就让清单不一致时构建失败。
