# 架构

写代码之前，先把这次改动碰到的每个系统摸清楚，再为它画两种不同的形状（类型、签名、模块边界），选那种每一份状态只有一个主人、每件事只有一种做法、调用方需要知道得最少的。变通办法反复出现时，重新设计，不要往上打补丁。

设计很大，或还在争，就跑 **arena** 技能，不要一个人画。
