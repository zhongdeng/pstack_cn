# Swarm

## 开始

在启动任何东西之前，打开一份待办清单，每个阶段一条。

1. 框定
2. 扇出
3. 汇总
4. 报告

## 阶段 A：框定

1. 陈述完成谓词，以及 swarm 必须返回的产物或报告。
2. 选择形状。划分成切片，让 N 个工作单元在相同的任务书上竞赛，或者两者混合。对于竞赛或混合形状，在启动之前声明 `first pass`、`rank all` 或 `best-of`。
3. 从 `~/.cursor/rules/pstack-models.mdc` 的 `swarm workers` 行挑选工作单元模型。如果规则或那一行缺失，就用 `grok-4.7-xhigh-fast`。对于 `auto` 或 `inherit-parent`，省略 `model`，这样工作单元跑在父模型上。如果 Task 工具拒绝一个 slug，就用默认值并说明。如果它拒绝默认值，就用它的错误信息里同一家族中最接近的有效 slug。对于模型竞赛，事先点明每一臂的模型。按 **poteto-mode** 技能的 Subagents 一节，为这项工作选择每个子代理的推理级别以及快速或标准速度。
4. 当工作单元要写东西时，给每个工作单元它自己的可写输出。当工作单元要验证或测量提交时，每份任务书点明确切的 SHA。测量任务书还要点明方法（样本数、一个样本是什么、顺序）。工作单元在它的结果里把两者都记下来。

## 阶段 B：扇出

在一条消息里启动全部 N 个工作单元，带上 `subagent_type: generalPurpose`、`environment: "cloud"`、`run_in_background: true`，以及第 3 步的模型，对于 `auto` 或 `inherit-parent` 则留空不设。只有当工作单元需要访问用户电脑上的某样东西时，才用 `environment: "local"`。

当工作单元必须从一个非默认的、已推送的分支开始时，传入 `cloud_base_branch`。

每份任务书都自成一体。包括目标、范围、确切的切片或竞赛中的一支、如何验证，以及报告什么。报告使用 `PASS`、`ISSUES` 或 `BLOCKED`，并附证据。能够证明一个缺陷的工作单元报告 `ISSUES`，并列出它能证明的每一个问题，而不只是第一个。

如果一个工作单元掉线，就用 N-1 继续，并注明。

## 阶段 C：汇总

读取最终结果。丢掉没有记下其任务书所点名的 SHA 和方法的结果，并把该工作单元重新启动一次。第二次仍然没有，就记一处缺口。缺口不算通过。对于覆盖，每一个必需的切片都需要一个结果。对于竞赛，应用事先声明的选择规则。使用 first pass、rank all 或 best-of。不要粘贴工作单元的原始倾倒。

## 阶段 D：报告

返回一份合并后的对话内报告，包含结果表、问题的一行摘要、缺口或掉线，以及使用了的竞赛规则。
