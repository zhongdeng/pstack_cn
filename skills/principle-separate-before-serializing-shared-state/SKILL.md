# 先分开，再串行化共享状态

并发参与者可能写同一个文件、分支、键或对象时，先问他们是需要同一个共享对象，还是各自在发布独立的事实。默认给每个参与者自己的文件、键、分支或状态目录，只在读取状态的地方合并。两个工人各自把自己的字段写进同一个 `state.json`，仍然是共享写入。

只有当单一共享写入目标是真正的不变量时，才用结构把访问串起来（锁文件、单一写入者、顺序阶段、比较并交换）。说明文字不是并发控制。「我们需要一把锁」是先要查的异味，不是默认答案。
