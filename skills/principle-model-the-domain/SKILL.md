# 为领域建模

用数据结构来表达领域，不要把它散在条件分支里。对的结构让非法状态无法表示，并删掉分支。

优先用状态机，而不是散落的布尔或阶段检查；用带类型的模型，而不是松散的参数；用映射、注册表或可区分联合，而不是散在多个文件里的分支；用 reducer，而不是随手改状态；访问方式需要时，用索引、队列或规范化的集合。

不要硬套。形状已经清楚、就在本地、也不大会长大时，就留着直白的代码。不信任那种只增加间接、却没有删掉分支或非法状态的抽象。

你跳过了这条的迹象：一个功能让 if/else 链又多了一支，或者又出现一个必须和第一个保持同步的布尔。
