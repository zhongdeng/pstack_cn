# 创建一个形式化验证 skill

测试检查的是有人想到要写的那些情况。形式化验证检查的是一个说定的范围里的每一种情况：模型里步骤的每一种顺序、某个界限内的每一个输入，或每一个输入。这个 skill 找出仓库里这件事最要紧的那一部分，验证它的一条性质，并留下一个项目本地的 skill，让下一个 agent 能拿一次改动去对那条性质。把那个 skill 写给这样一个 agent：它在改到一半时毫无上下文地读到这份文档，而且从没见过你的工作。用户必须能信任这个结果并据此行动，而不必学会那种验证语言。

## 从代码里选定目标

从代码库里找答案，只有你观察不到的才去问用户。如果用户点名了一个区域或一个缺陷，就从那里开始。

好目标是代码做出的一项承诺：打破它会伤害用户，而测试很少够到打破它的那种情况。选仓库里最强的这样一个目标，不是最好验证的那个。

## 让问题来选工具

选能以最低代价回答这个问题的工具：模型检测器、证明助手、SMT 支撑的验证器，或其他工具。事件会不会以坏的顺序发生，通常适合用模型检测器跑设计的一个小模型，任何语言里这件事的默认都是 TLA+。代码本身对每一个输入的行为是否成立，比如内存安全、溢出或数据结构不变量，通常适合用直接跑在代码上的验证器。如果没有验证器能跑在这门语言上，就如实说明，并用生成的输入测试真实代码，而不是给这个函数手写一个模型。必须在每一种规模上都成立、界限不够用的性质，可能需要一份证明。优先选这个仓库的开发者装得上、跑得了的工具，并告诉用户你为什么选它。

## 怎样才算好

- **忠实于代码。** 模型或证明的每一部分都指向审阅者打得开的代码。验证当成一个不可分割步骤的，在代码里也是一个不可分割的步骤。名字来自这个仓库。
- **能够失败。** 你从没见过它失败的检查，什么也证明不了。让每条性质在它所守护的代码的一个破坏变体上失败，比如去掉一处检查，或重排一个步骤。
- **发现保持为发现。** 当前代码打破这条性质时，用代码自己的说法报告它，并附上反例。不要把性质或模型放宽到它能通过为止，也不要改产品代码，除非用户要求。
- **对范围诚实。** 说明验证了什么、在哪些界限和假设之下，以及留下了什么。一次通过覆盖的是模型或那个界限，不是整个系统。
- **不靠工具也能读。** 性质和危害各用一句白话写明。把反例讲成一小串步骤，用代码里的说法。
- **重跑便宜。** 一条命令、一个可复现的工具版本，以及一次短到下一个 agent 愿意在每次相关改动上都用它的运行。
- **和代码保持同步。** 记下每项检查覆盖哪些文件和函数，以及你最后一次确认验证仍然描述它们的那个 commit。那个 commit 之后被覆盖的代码变了，下一个 agent 就能看出验证需要再看一眼。

## 生成验证 skill

写一个项目本地的 skill，frontmatter 里点名这个区域，并说明什么时候用它。没有 frontmatter，这个 skill 永远不会注册。只靠这个 skill，下一个 agent 就必须能判断一次改动有没有碰到已验证的代码、跑这项检查、区分真正的缺陷和建模错误，并在改动是有意的时候更新验证。把覆盖记录和同步 commit 放进 skill，并告诉下一个 agent：只有确认验证描述的是新 commit 上的代码之后，才把同步 commit 往前移。用这个仓库真实的命令、路径和名词，不要留占位符。

如果检查是一个 TLA+ 模型，告诉下一个 agent 用 pstack 的 [`/statechart`](../statechart/SKILL.md) skill 阅读每一个结果。它把检测器找到的每一处不变量违反，用白话显示成最短路径。检查通过时，`/statechart` 会画出系统如何在状态之间移动。用名字引用 `/statechart`。它的命令、选项和文件路径会随版本和机器变化，所以一个都不要抄进生成的 skill 或它的脚本。

## 移交之前先证明

按下一个 agent 的方式，把生成的 skill 走一遍，用一处会在真实代码里打破这条性质的临时改动。它必须抓住这个破坏。然后丢掉这处临时改动，确认检查回到起点：通过，或者只在你将要报告的发现上失败。从没跑过的验证 skill 只是草稿。如果 skill 漏掉了这个破坏，或某一步跑不起来，修 skill 或验证，不要修那处临时改动。

## 移交

告诉用户你验证了什么、用了哪个工具以及为什么、界限是什么、检查用白话发现了什么、怎么跑它，以及它不覆盖什么。只有找到一个挨得很近的第二目标时才建议它。改动之后没有重新检查验证时，让用户去用 `/maintain-formal-verification-skill` 把验证拉回对齐。
