# 不要注释

启动 Comment Sicko。对已接受的发现采取行动。

听从 Comment Sicko 的新视角。

## 范围

使用调用方的文件或 diff。否则使用相对基线分支的当前 diff，默认 `main`，包括工作树。

## 步骤

1. 用 `subagent_type: "comment-sicko"` 启动 `Task`。传入范围。按 **poteto-mode** 技能的 Subagents 一节，为这项工作选择每个子代理的推理级别以及快速或标准速度。不要复述它的规则。
2. 检查它的报告和 diff。拒绝应用代码编辑、范围逃逸、受例外保护的删除、陈述错误的 `MUST KILL` 理由，以及把有意保留的代码当成有罪的标记。对我们自己代码中意外之处的重塑标记仍然可执行。不要恢复那些注释。一条保留只有在证明它涉及我们无法更改的事物时才成立。审计遗漏的、限定了范围的 lint 与 TypeScript 抑制。正确性或安全性的抑制仍然是可执行的 `MUST KILL`。只有带着确切的例外和限定范围的证明，才恢复删除。在接受单薄的 `IMPORTANT` 或 `do not remove` 删除或保留之前，对它们的符号运行 `/how` 或 `/why`。如果一条删除含糊，不要恢复。如果一条保留被驳倒，或仍然含糊，就删掉它。撤销并重跑一份被拒绝的报告，并点明失败之处。第二次再拒绝，就把它作为未解决项报告，并使 `/no-comments` 失败。
3. 直接修掉琐碎的已接受标记：删掉一条死路径、去掉一个参数，或改用真正的 API。如果任何修复需要一个形状，就对已接受的那一组及其周围代码运行一次 `/architect`。停在草图。由 architect 定形状。第 4 步来实现。
4. 实现范围内最小的根因修复。去掉每一个被点名的权宜做法。如果根因在范围之外，就落地范围内最小的修复，并将其余部分作为未解决项报告。**principle-fix-root-causes** 和 **principle-redesign-from-first-principles** 技能只指导意图。两者都不授权把围栏放宽，也不授权修围栏外面的实例。绝不要外挂症状防护。
5. 约束注释会说 `do not remove`、`do not change wording` 或 `talk to X before changing`。留下那些关于我们无法更改的事物的保留。提供范围内最便宜的类型、运行时、测试或 CI lint。等待交互式批准。无人值守和 eval 需要调用方预先批准。如果批准了，先编码再删除。否则就删除，把约束作为未解决项报告，并勾勒范围之外的工作。
6. 报告删除数量、恢复的注释、重跑、architect 草图、修复、编码提议、已做的编码、未强制的约束，以及其他未解决的工作。
