# 面向结果的执行

优化那个预期中、可验证的终态，而不是维持平滑的中间状态。

**为什么：** 让每一步中间状态都完全稳定，常常会造出临时兼容代码，并变成长期债务。向目标架构收敛，并在明确的验证边界上证明正确性。

**核心规则：**
- 终态完整性优先于过渡期稳定
- 中间破损可以接受，前提是它在计划内、范围明确、并且可逆

**护栏：**
- 用于有明确阶段边界的计划性重写和迁移
- 声明哪些地方允许临时破损
- 迁移期间，对正在改动的区域保留高信号检查
- 计划完成时要求完整的静态与运行时验证
