# 结果导向执行

为预期的、可验证的最终状态做优化，而不是维持平滑的中间状态。

**为什么：** 让每个中间步骤都保持完全稳定，往往会写出临时兼容代码，而这些代码会变成长期债务。向目标架构收敛，并在明确的验证边界上证明正确性。

**核心规则：**
- 最终状态的完整性优先于过渡期的稳定性
- 只要中间状态的破坏是有计划的、范围明确的、可回退的，就可以接受

**护栏：**
- 用于带有明确阶段边界的计划性重写和迁移
- 明确声明哪里可以接受临时破坏
- 迁移过程中，对正在改动的区域保留高信号检查
- 计划完成时，要求完整的静态验证和运行时验证
