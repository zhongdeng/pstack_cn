# 修根因

调试时，修故障本身，别修它冒出来的地方。症状只是错误状态变得可见的位置。根因是系统第一次做了不该做的事，或者没能处理它本该处理的状态。

**为什么：** 修症状会把证据藏起来，让故障自由地在别处冒头。每修一次症状，系统就更难推理，因为代码里现在多了一个没人说清是什么 bug 的绕行方案。

**做法：**
- 先复现。
- 每一步都问"为什么"，直到答案落在代码里的某个错误决策上，而不是前一个决策的后果。
- 卡住就加埋点。读真实的报错和真实的状态。别猜。
- 问触发症状的那个状态是否合法。如果系统可能处于那个状态，那么在这个状态上崩掉的代码就是根因，在那里处理这个状态才是修复。如果那个状态本就不该存在，在崩掉的地方加检查只会把 bug 藏起来。去找是什么产生了这个状态。守卫、重试、吞掉错误、钳制取值、丢弃状态，都是藏 bug 的常见手法。
- 如果某个东西只在重启后失败，先怀疑持久化状态：配置文件、缓存、锁文件、序列化状态。
- 找模式，不只找个例。找出所有有同样故障的地方，一起修。
- 如果某个绕行方案需要一整段注释来为它辩护，那错的是代码。修代码，别修注释。
- 如果决定性的那个事实是深挖才找到的，就提出那个便宜、常开的信号，让它在第一眼就能暴露出来。
