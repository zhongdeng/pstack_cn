# 修复根因

调试时，修故障本身，而不是修它显露出来的地方。症状是错误状态变得可见的地方。根因是系统第一次做了它不该做的事，或没有处理它本该处理的状态的地方。

**为什么：** 修症状会藏起证据，并让故障自由地在别处显露。每一次都让系统更难推理，因为代码现在带着一个没人命名的 bug 的权宜之计。

**模式：**
- 先复现。
- 在每一步问“为什么”，直到答案是代码里的一个错误决定，而不是更早那个决定的后果。
- 卡住时，加观测。读真正的错误和真正的状态。不要猜。
- 问触发症状的那个状态是否合法。如果系统可以处于那个状态，在它上面崩溃的代码就是根因，在那里处理这个状态就是修复。如果这个状态根本不该存在，在崩溃处加检查会藏住 bug。找出是什么产生了这个状态。守卫、重试、吞掉的错误、夹紧的值、丢掉的状态，是藏 bug 的常见方式。
- 某件事只在重启后失败时，先怀疑持久化状态：配置文件、缓存、锁文件、序列化状态。
- 检查的是这个模式，而不只是这一处实例。找出每一处同样的故障，全部修掉。
- 如果一个权宜之计需要一段话那么长的注释来辩解，代码就是错的。修代码，而不是修注释。
- 如果那个决定性事实要深挖才找得到，就提议一个便宜、始终开启的信号，让它在第一眼就能显出来。
