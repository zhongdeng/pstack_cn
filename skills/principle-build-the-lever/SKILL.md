# 建造杠杆

工作不琐碎时，就造一个工具来做它（codemod、脚本、生成器，或可以重跑的检查），不要手工做。门槛是琐碎与否，不是重复与否。只有两三处一眼能看完的编辑，才可以不做工具。

- 先手工做第一个单元，再造工具，并在那个单元上重跑来证明它。让它重跑是安全的。
- 确定性的工具胜过扇出。真要扇出时，把做法、验证约定和禁区写成一份技能，让受托方去读，并且改不了它。
- 用了这条原则，diff 里就该有一个文件。没有脚本、codemod、生成器或受托方技能，就等于没用。工作会活过这次会话时，把它提交进去。
- 造能完成或证明这件事的最小脚本，不要造框架。
