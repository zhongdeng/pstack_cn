# 控制适配器契约

Benny 并不知道如何启动或驱动每一个应用。用户必须为目标应用配置一个实现本契约的控制技能或适配器。

在 `control.skill_name` 里设置它的技能名。

在 `control.feature_map_path` 里设置填写完成的用户可见功能地图路径。把 [`feature-map.example.md`](./feature-map.example.md) 复制到 `.cursor/automations/benny/` 之外再填写，不要直接改复制过来的示例。

如果技能、功能地图或某项必需能力缺失、含糊或不完整，复现和修复工作必须失败关闭。

## 必需能力

### 启动

在指定的测试环境里启动指定版本的应用。

输入：

- 仓库和版本
- 构建或启动模式
- 工作区、账号、fixture 和功能状态要求
- 产物目录
- 填写完成的功能地图路径

返回：

- 会话标识
- 适配器如何确认应用和环境正确
- 稳定的应用标记
- 后续调用需要的运行进程或目标详情
- 任何缺失的能力

适配器必须能把目标应用和相似的窗口、shell 或生产实例区分开。

### 驱动 UI

执行真实的用户操作：

- 点击
- 输入
- 按键
- 滚动
- 拖拽
- 调整窗口大小
- 通过应用控件导航

优先使用角色、标签和稳定选择器。只有在截取最新截图之后才使用坐标。

返回每个操作以及观察到的状态变化。

不要通过设置内部状态、调用隐藏的应用方法、直接写存储或注入 DOM 改动来制造症状。

### 驱动已映射的功能和状态

在驱动应用之前，先读相关的功能地图章节。

适配器必须提供以下方式：

- 通过用户可见路径进入每一个已映射的功能。
- 调用该功能列出的适配器动作名。
- 在适用时与 default、hover、focus-visible、active、disabled、loading、empty、error、selected、open、expanded 以及功能特有的状态交互。
- 通过安全的 fixture 数据、权限、flag、服务响应或受支持的测试控件来布置某个状态。
- 为第二次独立复现尝试重置该功能。
- 按功能地图指定的方式截取截图、录制视频并做只读交叉核对。

使用角色、可访问名称、ARIA 关系、稳定的组件标记和按用途命名的 data 属性。绝不要使用生成的 CSS 或 StyleX 类名、动态哈希、子节点索引或脆弱的 DOM 位置。

布置前置条件不等于允许注入被报告的症状。复现本身仍然必须来自真实的用户交互。

### 检查状态

读取状态以确认 UI 显示了什么。

示例：

- 可访问性树
- DOM 或视图层级
- 进程状态
- 本地日志
- 网络请求状态
- 应用暴露的调试状态

检查是只读的。如果某个查询会改变状态，它属于 `drive UI`，并且必须代表真实的用户操作。

### 截图

把当前应用状态截取到指定路径。

返回：

- 文件路径
- 截取时间
- 应用标记或窗口标题
- 应该可见内容的简短描述

截图必须包含足够的应用界面元素，以证明被测的是正确的应用。

### 录制

围绕完整复现路径开始和停止屏幕录制。

返回：

- 文件路径
- 开始和停止时间
- 录制的窗口或区域
- 是否省略了音频或敏感浮层

录制必须展示有区分度的最终状态，而不只是布置过程或加载界面。

### 清理

停止适配器创建的进程和会话。

移除一次性的：

- 浏览器或应用配置
- 临时工作区
- 适配器自己创建的测试账号或 fixture
- 调试端口和隧道
- 超过保留期的录制文件

返回哪些被停止、移除、保留，或留给人工处理。

清理不得删除用户的工作。

## 适配器行为

适配器必须：

- 在复现开始前报告能力。
- 报告它能驱动哪些功能地图章节，哪些被阻塞。
- 基线和修复后的构建使用相同的环境输入。
- 把启动失败当作失败上报。
- 限制重试次数。
- 让密钥不出现在日志和产物里。
- 把录制文件放在仓库之外。
- 在两次复现尝试之间支持全新或重置的状态。
- 除非用户明确配置了安全的测试操作，否则避免改动生产环境。

## 环境转译

在宣布环境阻塞之前，先去掉平台特有的名词重述缺陷，并询问同样的行为能否在可用环境里安全测试。

示例：

- 指定的浏览器可能指任意外部浏览器。
- 指定的按键可能指配置好的快捷键。
- 指定的远程主机可能指延迟或断开的远程目标。

只有在测试同一底层行为时才使用转译后的尝试。把它标记为转译证据。当缺失的环境本身就是缺陷的一部分时，不要称它为精确复现。

硬件提示、操作系统权限对话框、仅设备可用的 API 和不可用的账号状态可能是真正的阻塞。

## 设置检查

在启用复现自动化之前，先跑一次无害的适配器检查：

1. 启动应用。
2. 确认稳定的应用标记。
3. 加载一个填写完成的功能地图章节。
4. 通过该功能的用户路径进入它。
5. 通过已映射的适配器动作触发一个一次性状态。
6. 检查产生的状态。
7. 截一张图。
8. 录一段短片段。
9. 清理。

只有当全部九步都成功，并且不涉及 source-channel Slack 帖子时，才启用复现工作。
