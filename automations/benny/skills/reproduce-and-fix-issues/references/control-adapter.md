# 控制适配器契约

Benny 并不知道如何启动或驱动每一个应用。用户必须配置一个实现本契约的控制 skill 或适配器，供目标应用使用。

在 `control.skill_name` 中设置它的 skill 名称。

在 `control.feature_map_path` 中设置已完成的、面向用户的功能映射路径。把 [`feature-map.example.md`](./feature-map.example.md) 复制到 `.cursor/automations/benny/` 之外再填写，不要编辑复制来的示例。

如果该 skill、功能映射或某项必需能力缺失、含糊或不完整，复现和修复工作必须失败即关闭。

## 必需能力

### 启动

在所要求的测试环境中启动所要求的应用修订版本。

输入：

- 仓库和修订版本
- 构建或启动模式
- 工作区、账号、fixture，以及功能状态要求
- 产物目录
- 已完成的功能映射路径

返回：

- 会话标识
- 适配器如何确认应用和环境是正确的
- 稳定的应用标记
- 后续调用所需的、正在运行的进程或目标详情
- 任何缺失的能力

适配器必须把目标应用与相似的窗口、shell 或生产实例区分开。

### 驱动界面

执行真实的用户操作：

- 点击
- 输入
- 按键
- 滚动
- 拖拽
- 调整大小
- 通过应用控件导航

优先使用角色、标签和稳定选择器。只有在拿到一张新截图之后才使用坐标。

返回每一个操作，以及观察到的状态变化。

不要通过设置内部状态、调用隐藏的应用方法、直接写入存储，或注入 DOM 变更来制造症状。

### 驱动已映射的功能与状态

在驱动应用之前，阅读相关的功能映射小节。

适配器必须提供办法来：

- 经用户可见路径导航到每一个已映射功能。
- 调用该功能所列出的适配器操作名。
- 在适用时，与 default（默认）、hover（悬停）、focus-visible（焦点可见）、active（激活）、disabled（禁用）、loading（加载中）、empty（空）、error（错误）、selected（已选中）、open（打开）、expanded（展开），以及功能特有状态交互。
- 通过安全的 fixture 数据、权限、功能开关、服务响应或受支持的测试控件来安排一种状态。
- 为第二次独立的复现尝试重置该功能。
- 采集功能映射所指定的截图、视频和只读交叉核对。

使用角色、无障碍名称、ARIA 关系、稳定的组件标记，以及按用途命名的 data 属性。绝不要使用生成的 CSS 或 StyleX 类名、动态哈希、子元素序号，或脆弱的 DOM 位置。

安排前置条件并不等于允许注入所报告的症状。复现本身仍然必须来自真实的用户交互。

### 检查状态

读取状态，以确认界面显示的内容。

示例：

- 无障碍树
- DOM 或视图层级
- 进程状态
- 本地日志
- 网络请求状态
- 应用暴露的调试状态

检查是只读的。如果某次查询会改变状态，它就属于 `drive UI`，并且必须代表真实的用户操作。

### 截图

把当前应用状态截取到所要求的路径。

返回：

- 文件路径
- 采集时间
- 应用标记或窗口标题
- 对应当可见内容的简短描述

截图必须展示足够的应用外壳，以证明受测的是正确的应用。

### 录屏

围绕完整的复现路径开始并停止一次屏幕录制。

返回：

- 文件路径
- 开始时间和停止时间
- 采集的窗口或区域
- 是否省略了音频或敏感浮层

录屏必须展示区分性的最终状态，而不能只有准备过程或加载画面。

### 清理

停止适配器创建的进程和会话。

移除用后即弃的：

- 浏览器或应用配置档
- 临时工作区
- 适配器所创建的测试账号或 fixture
- 调试端口和隧道
- 超过保留窗口的采集物

返回已停止、已移除、已保留，或留给人处理的内容。

清理不得删除用户的工作。

## 适配器行为

适配器必须：

- 在复现开始之前报告自身能力。
- 报告它能驱动哪些功能映射小节，哪些被阻塞。
- 对基线构建和修补后的构建使用相同的环境输入。
- 把启动失败如实呈现为失败。
- 限制重试次数。
- 不要让密钥进入日志和产物。
- 把采集物放在仓库之外。
- 支持在两次复现尝试之间使用全新状态或已重置状态。
- 避免改动生产环境，除非用户明确配置了一个安全的测试操作。

## 环境转译

在宣布环境阻塞之前，用不含平台专有名词的方式重述缺陷，并询问同一行为能否在可用环境中安全地测试。

示例：

- 点名的某个浏览器，可以指任意外部浏览器。
- 点名的某个按键，可以指已配置的快捷键。
- 点名的某台远程主机，可以指延迟或已断开的远程目标。

只有当转译后的尝试检验的是同一底层行为时，才使用它。把它标为转译证据。当缺失的环境本身就是缺陷的一部分时，不要称之为精确复现。

硬件提示、操作系统权限对话框、仅设备可用的 API，以及不可用的账号状态，都可能是真正的阻塞。

## 设置检查

在启用复现自动化之前，做一次无害的适配器检查：

1. 启动应用。
2. 确认稳定的应用标记。
3. 加载一节已完成的功能映射。
4. 经用户路径导航到该功能。
5. 通过已映射的适配器操作演练一个一次性状态。
6. 检查由此产生的状态。
7. 截取一张截图。
8. 录一段短片。
9. 清理。

只有当这九步全部成功，且没有涉及来源频道的 Slack 发帖时，才启用复现工作。
