# 设置 Benny

Benny 以 pstack 内部一个休眠的自动化包的形式提供。插件清单只暴露 pstack 常规的 skill 根；本文件和那两个操作文件都不是 slash skill。

用户通过让 Cursor 指向该包的 `FOR_AGENTS.md` 来进入设置。引导流程把整包复制进目标仓库，然后直接读取 `.cursor/automations/benny/skills/setup-benny/SKILL.md` 处的本文件。

Benny 需要外部配置，以及两个实际运行的 Cursor 自动化。

在用户明确要求之前，不要创建或更新自动化。绝不要把密钥值放进插件文件、提示词或已提交的配置。

## 1. 复制该包并启用共享的 pstack skill

在询问 Benny 配置之前，以及在调用内置的 `/automate` skill 之前，先做这一步。

询问哪个仓库将运行这些自动化。源包是包含 `FOR_AGENTS.md` 的那个目录。目标位置是 `<target-repository>/.cursor/automations/benny/`。

把整个源包合并到目标位置：

1. 目标位置不存在时，创建它。
2. 把每一个源文件复制到相同的相对路径。
3. 保留仅存在于目标位置的文件。在安装或刷新期间，绝不要删除无关文件。
4. 把用户自有的配置、功能映射和路由映射留在目标位置之外。绝不要覆盖它们。
5. 当已有的、由源包管理的文件内容不同时，检查 diff 并合并，不要丢弃本地修改。如果归属不明确，先停下来询问，再替换它。
6. 验证目标位置包含 `FOR_AGENTS.md`、本设置文件、两个操作文件、它们的参考资料，以及模板。

如果本文件已经是从目标位置读取的，就把复制视为完成，并在继续之前做同样的验证。

把 pstack 加到目标仓库的 `.cursor/settings.json`。如果该文件或 `.cursor` 目录不存在，就创建它。

把下面这项合并进现有的 JSON 或 JSONC：

```json
{
	"plugins": {
		"pstack": { "enabled": true }
	}
}
```

保留每一项无关的顶层设置，以及其他每一个插件条目。如果 `plugins.pstack` 已经存在，只改它的 `enabled` 值。当文件使用 JSONC 时，保留注释和有效的 JSONC 语法。编辑之后校验该文件。

重新加载目标项目，或启动一个以该处为根的新代理。验证这些共享的 pstack skill 能从项目作用域解析出来：

- `how`
- `why`
- `tdd`
- `unslop`
- `principle-separate-before-serializing-shared-state`
- `principle-minimize-reader-load`
- `principle-guard-the-context-window`
- `principle-sequence-verifiable-units`
- `principle-fix-root-causes`
- `principle-prove-it-works`

不要把从当前会话或用户作用域插件加载的 skill 算进去。这项检查必须表明：目标仓库里的一个新代理，是通过项目设置获得 pstack 的。

如果项目作用域的插件安装不可用，或任何共享依赖无法解析，就停下来并说明失败原因。

Benny 的文件直接从 `.cursor/automations/benny/` 读取。不要把该目录加进插件清单，也不要指望它的 `SKILL.md` 文件出现在 slash skill 列表里。

告诉用户：在启用任何一个自动化之前，必须先提交 `.cursor/settings.json`、`.cursor/automations/benny/`，以及任何被引用且不含密钥的配置。除非用户要求，否则不要提交它们。

一旦这项检查通过，实际运行的自动化提示词就可以按其稳定的、相对仓库的路径，读取已提交的操作文件。它们不得嵌入插件缓存路径，也不得复制文件内容。

## 2. 改写配置

打开这些已复制的示例：

- `../../templates/configuration.example.yaml`
- `../reproduce-and-fix-issues/references/feature-map.example.md`

在 `.cursor/automations/benny/` 之外创建用户自有的副本。它们是配置文件，不是包文件。示例位置：

- 项目配置，例如 `.cursor/benny/configuration.yaml`
- 项目功能映射，例如 `.cursor/benny/feature-map.md`
- 项目路由映射，例如 `.cursor/benny/routing.md`
- 用户配置，例如 `~/.config/benny/configuration.yaml`
- 用户功能映射，例如 `~/.config/benny/feature-map.md`

为自动化可能复现的每一个面向用户的功能，填写一节功能映射。让它保持在用户视角。不要把实现细节或当前代码路径冻结进这份映射。

不要编辑复制来的示例。包刷新可以在冲突审阅之后更新由源包管理的文件，但绝不能动用户自有的副本。

当一次全新的自动化检出必须读取这些文件时，优先使用目标仓库里已提交、不含密钥的文件。否则，把必需的值转述进实际运行的提示词。只有在内置的 `/automate` skill 确认该文件已提交到自动化运行所在的仓库之后，才引用仓库里的文件。

对已提交的包文件和配置文件，使用稳定的、相对仓库的路径。绝不要从实际运行的自动化去引用插件源目录或插件缓存路径。

## 3. 填写必需的选择

询问或确认：

- 来源 Slack 频道 ID
- 可选的运维频道或状态频道 ID
- 仓库 URL 和默认分支
- 分诊身份或 Slack 用户 ID
- 问题跟踪器的类型、团队、项目、标签和入库状态
- 跟踪器适配器 skill 或 MCP 操作
- 可选的路由映射路径
- 必需的控制 skill 名称
- 必需的、面向用户的功能映射路径
- 状态 emoji 字符串
- pull request 的 URL 格式
- 轮询预算和工作量预算
- 分诊、复现、代码工作和媒体审阅所用的模型 slug

只使用用户的 Cursor 模型选择器，或受支持模型列表中显示为可用的模型 slug。不要猜测 slug，也不要沿用私有的默认值。

来源频道、分诊身份、仓库、跟踪器适配器、控制 skill 和功能映射必须明确。如果任何必需值仍然含糊，设置即失败。

在保存之前，对最终的自动化名称、描述和提示词垫片使用 pstack 的 `unslop` skill。

## 4. 检查集成能力

分诊自动化需要：

- 读取已配置来源 Slack 频道及其话题串的权限
- 在该频道中回复话题串的权限
- 当报告包含媒体时，读取附件元数据和下载文件的权限
- 通过已配置的问题跟踪器适配器进行搜索、读取、创建和更新的权限

复现自动化需要：

- 读取来源话题串的权限
- 在来源频道中回复话题串的权限
- 在已配置的运维频道中发送和编辑的可选权限
- 读取仓库和历史的权限
- 一个能够打开草稿 pull request 的 pull request 操作
- 已配置的控制适配器 skill

读取和发送优先使用已配置的 Cursor Slack 操作。可选的 `BENNY_SLACK_BOT_TOKEN` 可以填补一个狭窄缺口，例如编辑一条运维状态消息，或下载一个附件。把这个值存在密钥管理器或环境变量里，不要写进 YAML。

不要使用没有文档的集成端点。

## 5. 准备路由映射

如果用户想要改派或负责人提醒：

1. 把 `../triage-issue-reports/references/routing.example.md` 复制到 `.cursor/automations/benny/` 之外。
2. 把每一个占位符替换成公开的值，或组织内部的值。
3. 默认关闭负责人提醒。
4. 只允许提醒已配置的功能负责人，或已确认的、可能的回归作者。

如果没有配置路由映射，分诊可以给报告分类，但不得猜测目的地或负责人。

## 6. 验证控制适配器

阅读 `../reproduce-and-fix-issues/references/control-adapter.md`，以及用户已完成的功能映射。

确认所指名的 skill 能够：

- 启动目标应用
- 通过真实界面导航到每一个已映射功能
- 通过已声明的适配器操作演练已映射的状态
- 检查状态，而不强行制造结果
- 截取截图
- 开始并停止录屏
- 清理它自己的进程和临时数据

如果任何能力缺失，就让复现自动化保持禁用。它必须失败即关闭，而不是声称做了一次它并没有执行的复现。

## 7. 准备实际运行的自动化

询问这是首次创建，还是在配置已有的自动化。

从已复制的包中阅读 `../../FOR_AGENTS.md`，把它作为两条路径上用户意图的主要来源。用它来理解两个触发条件、工具、指令、结果和共同规则。

### 首次创建

一次只创建一个自动化。

对于每一个自动化：

1. 把与之匹配的、已复制的提示词模板，当作次要的内部源材料来读。
2. 把 `FOR_AGENTS.md`、填写完成的 Benny 配置，以及模板意图，转成一份完整的自然语言请求。
3. 让实际运行的提示词读取并遵循 `.cursor/automations/benny/` 下它那份确切的、已提交的操作文件。
4. 使用稳定的、相对仓库的路径，而不是插件源路径或缓存路径。不要把操作文件的内容复制进实际运行的提示词。
5. 阅读并遵循内置的 `automate` skill。
6. 让 `automate` 去发现 Slack 频道、仓库，以及已连接的集成。
7. 让 `automate` 确认：已复制的包，以及任何被引用的配置文件，都已经提交到自动化将要运行的同一个仓库。
8. 让 `automate` 展示它的草稿表、取得批准、询问是否就绪，并打开 Automations 编辑器。
9. 先完成这个自动化的编辑器交接，再开始下一个。

把下面这份按配置填好的完整分诊意图交给 `automate`：

- 名称为 `benny-triage`。
- 每一次运行都读取并遵循 `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md`。
- 对已配置来源 Slack 频道中的每一条新顶层报告触发。
- 阅读触发这次运行的话题串，并且只在其中回复。
- 使用已配置的问题跟踪器集成。
- 做分类、检查证据、追溯成因、去重，并且只创建明确的新 bug。
- 以一条仅在话题串内的结论结束，带上已配置的 `[benny:bug]`、`[benny:performance]` 或 `[benny:other]` 标记，以及可选的跟踪器 URL。
- 绝不要发送来源频道根消息。

分诊的编辑器交接完成之后，把下面这份完整的复现与修复意图交给 `automate`：

- 名称为 `benny-reproduce`。
- 每一次运行都读取并遵循 `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md`。
- 对已配置来源 Slack 频道中同样的那些新顶层报告触发。
- 使用已配置的仓库和默认分支。
- 阅读来源话题串，并且只在其中回复。
- 包含 pull request 的创建，以及已配置的跟踪器、控制适配器和功能映射要求。除非 `automate` 确认同一仓库里有一份符合条件的已提交文件，否则转述已映射的用户路径和状态。
- 在行动之前，等待一个可信的分诊标记。
- 通过已映射的真实界面，把完全相同的症状复现两次，并采集证据。
- 验证已有修复，不要在其之上另行编写改动。
- 只在确认复现之后，才尝试一次可选的限定范围修复；证据和检查都通过时，再打开草稿 pull request。
- 绝不要发送来源频道根消息。

不要重复 `automate` 在 Slack、仓库、集成、完整性、认证、草稿审阅、批准、就绪或编辑器交接上已经做的工作。

### 已有自动化

内置的 `automate` skill 只用于创建。不要用它来搜索、检查或更新已有的自动化。

先完成配置、路由、控制适配器和功能映射的验证。然后把下面这份简明的编辑器清单交给用户。

对于已有的分诊自动化，更新：

- 名称和描述
- 直接指示去读取 `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md`
- 新的顶层 Slack 报告触发条件，以及来源频道
- Slack 话题串的读取和回复能力
- 问题跟踪器集成
- 转述后的分诊指令、仅限话题串的规则，以及 Benny 的结论标记

对于已有的复现自动化，更新：

- 名称和描述
- 直接指示去读取 `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md`
- 与之匹配的 Slack 触发条件和来源频道
- 仓库和默认分支
- Slack 话题串的读取和回复能力
- pull request 操作
- 跟踪器、控制适配器和功能映射的要求
- 转述后的标记等待、证据、验证，以及限定范围修复的指令

请用户在各自的 Automations 编辑器里，直接更新每一个已有自动化。不要创建替代品，也不要创建重复项。

### 创建边界

绝不要调用直接的自动化后端服务，或后端自动化工具。绝不要使用携带草稿字段的浏览器 URL。绝不要构造或打开一条 Cursor 协议深链。对于新的自动化，唯一的完成路径是内置 `automate` skill 所提供的、经过审阅的 Automations 编辑器交接。

在编辑器保存之后、话题串安全测试通过之前，不要启用任何一个自动化。

## 8. 测试话题串安全

使用一个测试频道，或一条无害的测试报告。

测试之前，确认目标仓库的 `.cursor/settings.json`、`.cursor/automations/benny/`，以及每一个被引用且不含密钥的配置文件，都已经提交到自动化检出所用的那个分支上。确认两份实际运行的提示词都指向各自确切的、已提交的操作文件。如果任何一项检查失败，就停止。告诉用户自动化还不能启用。

验证：

1. 分诊存下根 `thread_ts`，并恰好以回复的形式发送一条结论。
2. 这条结论包含一个已配置标记。
3. 复现只接受来自已配置分诊身份的标记。
4. 复现保持同一组不可变的来源坐标。
5. 不出现来源频道根消息。
6. 被委派的工作者无法使用任何 Slack 写操作。
7. 坐标缺失、父消息已被删除，或预检失败时，不产生消息，也不产生跟踪器 issue。

只有这七项检查全部通过之后，才放行正常流量。
